# 运行配置与输入区设置

对应 [#46](https://github.com/yuzheng14/codex-web-ui/issues/46)。当前核验日期：2026-10-18；目标 Codex/app-server 0.163.0；协议以仓库生成的 `src/codex/generated` 为准。

## 页面显示什么

运行设置融合到输入框底部发送栏：左侧为添加图片、项目、权限模式及权限详情入口，右侧为合并的模型设置、发送/中断按钮。模型设置按钮展示模型名和推理强度，Fast 开启时附带闪电；点击后在同一弹层选择模型、强度和 Fast，右上角关闭按钮、Esc 或点击外部收起。窄屏保持单行，模型名按剩余空间省略，输入框宽度不超过 380px 时隐藏重复的项目标识，发送与中断按钮保持可见。权限模式提供请求批准、帮我批准、完全访问、只读四种完整选择；权限详情只读展示真实权限范围、profile、目录范围、审批策略、网络及审核方，见 [权限模式](permission-modes.md)。推理强度在弹层内使用仪表盘与准确值，未知档位显示问号；档位指示不代表计算量的比例。未修改时展示 app-server 返回值；修改后展示拟用值，并提示当前值、应用时机，提供「撤销修改」。只有收到匹配的服务器结果才清除待生效状态。

模型、推理强度和权限模式使用 shadcn/ui Select 的 Radix 实现，复用项目 CSS 配色；方向键导航、Enter 选择、Escape 关闭并返回触发器，点击外部关闭。菜单通过 Portal 渲染并限制在视口内，模型弹层中的菜单和 Tooltip 保持在该原生 Popover 的顶层内，长模型名在菜单中换行。仪表盘与发送按钮共用 shadcn/ui Tooltip，支持悬停和键盘聚焦、Escape 关闭，禁用时仍可悬停查看；打开强度菜单时隐藏。存在强度草稿时，提示同时列出待应用值和当前值。依赖 `@radix-ui/react-select@2.4.1`、`@radix-ui/react-tooltip@1.4.1` 及其必要传递依赖均已获批准，未引入 shadcn CLI。Tooltip 通过 Portal 定位并避让视口边缘；关闭选择菜单后，恢复焦点不会重新弹出提示。

| 页面状态              | 数据来源                                                                                           | 能确定的内容                                       | 读取时机                             |
| --------------------- | -------------------------------------------------------------------------------------------------- | -------------------------------------------------- | ------------------------------------ |
| 尚未选择会话          | `config/read({ cwd: 项目真实目录, includeLayers: false })`                                         | 分层解析后的磁盘配置；字段可能为空                 | 项目、运行实例变化，或读取失败后重试 |
| 已保存的历史会话      | `thread/read` 的 `Thread.model` / `reasoningEffort`                                                | 保存的模型和推理强度；不代表外部进程正在使用的配置 | 选择会话、刷新详情及元数据同步       |
| 新建、恢复、Fork 完成 | 对应 RPC 响应顶层 `model` / `reasoningEffort` / `sandbox` / `approvalPolicy` / `approvalsReviewer` | 服务器确认的会话配置                               | 操作响应返回                         |
| 已加载会话设置变化    | `thread/settings/updated.threadSettings`                                                           | `model`、`effort` 和完整权限策略的显示摘要         | 通知到达后推送到浏览器               |
| 运行实例重置          | 保留历史模型字段，清除旧权限摘要                                                                   | 历史保存值；恢复前权限未知                         | app-server 重启或实例变化            |

字段缺失显示“未报告”，不把 `model/list` 默认条目、模型建议强度或页面常量当成实际配置。模型目录只提供可选项；切换模型且原强度不受支持时，将目录建议值作为**待提交选择**。自定义模型、外部沙箱、细粒度审批策略原样保留其身份，不自动转换为普通预设。网络权限与权限范围分开展示；这里的摘要不是完整文件路径授权编辑器。

适配层只返回展示需要的白名单字段。`config/read` 中的凭证、指令和其他配置不会穿过 HTTP 网关。元数据读取只包含模型字段时，会保留本运行实例已经确认的权限；迟到的读结果不能覆盖更新的设置通知。加载另一会话期间不显示项目默认值。

恢复响应中的完整配置独立于状态、标题等通知合并：这些通知不能让权限摘要丢失；恢复期间收到更新的设置通知时，则保留该通知（包括明确的空值）。历史会话仍被其他进程占用、未能恢复时，权限保持“未报告”，不能拿项目默认配置冒充其实际权限。

## 配置来源、优先级与生效范围

手动选择模型或推理强度后，页面立即通过受保护的 `POST /api/projects/:projectId/model-defaults` 保存完整的模型/强度组合。网关复用 Codex CLI 0.162.1 选择器的 `config/batchWrite` 路径，以一次 replace 批处理写入 `model`、`model_reasoning_effort`，并设置 `reloadUserConfig: true`；无显式强度时写入 null 清除该项。配置位置由 app-server 决定，通常是其 `CODEX_HOME/config.toml`，也支持服务端当前使用的 profile；浏览器不能指定文件路径或其他配置键。写入使用现有操作 ID 和回执核对机制，不会自动重发结果未知的请求。依据见 [CLI 选择器](https://github.com/openai/codex/blob/rust-v0.162.1/codex-rs/tui/src/chatwidget/model_popups.rs#L291) 与 [原生配置批处理](https://github.com/openai/codex/blob/rust-v0.162.1/codex-rs/tui/src/config_update.rs#L87)。

保存的值供后续新会话使用，同一 app-server 的其他项目也可继承；更高优先级的项目或启动配置仍可能覆盖它。页面分别显示保存中、成功、被覆盖和未能确认保存的状态。保存期间禁止连续修改和新建会话，避免新会话抢在写入之前创建；收到成功回执后重新读取项目默认值。查看、恢复或切换历史会话不写默认配置。

默认值落盘与当前会话生效是两件事：已有会话仍沿用自己的实际设置，模型/强度草稿在下一轮或 Fork 时按原流程请求应用。“撤销本会话修改”只撤销该会话的草稿，不撤销已保存的新会话默认值。保存失败保留草稿，并提供显式重新保存入口。权限模式的选择、可用条件和生效范围沿用 #103 / #104；保存模型时不写任何权限、审批或审核方配置。

磁盘配置的分层解析交给 Codex。[官方配置说明](https://learn.chatgpt.com/docs/config-file/config-basic) 给出的优先级由高到低为：CLI 参数及 `--config`、受信任项目内从根到当前目录的 `.codex/config.toml`（更近者优先）、指定 profile、用户配置、云端管理默认值、系统配置、内置默认值。强制要求会限制可用值，不能把普通覆盖理解为可以绕过要求。此处是文档结论，并未逐一改动本机所有层做实验。

应用启动 `codex app-server --listen stdio://`；`codex.home` 仅设置该子进程的 `CODEX_HOME`。生产配置不提供任意 CLI 参数入口。应用也不自行读取 TOML、选择 profile 或推断最终默认模型。`config/read` 是磁盘分层结果，不是指定会话的实时查询接口，见 [App Server 文档](https://learn.chatgpt.com/docs/app-server)。

| 来源/操作            | 发送与读取方式                                                                                                                                                                                  | 作用范围和生效时机                                           |
| -------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------ |
| 本机、项目或启动配置 | Codex 解析；页面无会话时读取 `config/read`                                                                                                                                                      | 为新会话提供默认配置；已加载会话不保证随磁盘变化更新         |
| 项目概览中的手动选择 | 模型/强度立即保存完整默认组合；权限模式草稿仍作为一组整体提交                                                                                                                                   | 模型默认值供后续新会话使用；权限草稿仅作用于该项目的新建请求 |
| 当前会话中的手动选择 | `thread/start/fork`：模型及完整权限模式为顶层参数，强度为 `config.model_reasoning_effort`；`turn/start`：强度为 `effort`，完整权限模式为 `permissions` / `approvalPolicy` / `approvalsReviewer` | 创建/Fork 或下一轮开始时请求应用；以服务器响应、通知为准     |
| 保存的会话状态       | `thread/read` 读取模型字段；自动恢复不携带 UI 草稿，返回最终设置                                                                                                                                | 恢复沿用保存值；UI 草稿在恢复后的下一轮或 Fork 时提交        |
| 正在运行的任务       | 设置控件禁用；追加要求走 `turn/steer`，不带设置                                                                                                                                                 | 不在正在执行的轮次中暗改配置                                 |

会话草稿按 thread ID 隔离，权限模式的项目概览草稿按 project ID 隔离；切换会话会保留各自未发送选择。模型默认值保存成功后清除项目概览中的模型/强度草稿，防止旧项目草稿覆盖更新的默认值；会话草稿仍等待会话实际设置的确认。观察到的自定义权限不会自动回传。刷新页面会丢弃未提交的会话选择，再显示服务器值；已保存的模型默认值继续用于新会话。

本页面沿用主分支的自动恢复行为：选择空闲历史会话后自动恢复，实际占用时提示重试或 Fork。恢复不发送草稿覆盖。

本页面不自动轮询外部修改的配置文件。无会话状态下重新打开/刷新页面会再次请求默认配置；是否需要重启 app-server 才能使用特定磁盘改动由 Codex 决定，本次没有验证全部热加载行为。会话运行配置则随操作和通知更新；应用配置文件（如 `codex.binary`、`codex.home`）仍需重启网关生效。

## 已执行验证

模型默认值持久化另以真实 Codex/app-server 0.162.1 核验：使用全新的临时 `CODEX_HOME` 与工作目录，保存 `gpt-6.1-sol / high`，检查临时 config.toml 后停止并重新启动 app-server，新会话及 `config/read` 都保持这组默认值。写入前已创建会话的模型/强度保持原值，文件未写入任何权限键。该实验没有发送模型任务，也没有修改本机实际用户配置。

真实 app-server 实验使用新建的临时目录，不修改全局配置；为生成可恢复历史，仅发送一次“只回复 OK，不调用工具、不读写文件”的只读任务，任务完成。

| 场景                       | 请求/磁盘结果                                                                      | app-server 返回                                                    | 页面规则与验证                                                                                   |
| -------------------------- | ---------------------------------------------------------------------------------- | ------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------ |
| 默认创建                   | `config/read`：`gpt-6-astra / xhigh`；沙箱、审批为 null，reviewer 为 `auto_review` | 创建：`gpt-6-astra / xhigh`、`read-only`、`on-request`、网络 false | 创建前未报告的权限不猜测；创建后采用响应。真实 RPC + 模拟进程浏览器测试                          |
| 手动指定                   | 创建时传 `high`、`read-only`、`on-request`                                         | 返回相同值，任务后元数据仍为 `high`                                | 浏览器选择、待生效提示、发送后的确认及刷新由 E2E 覆盖；RPC 实验确认真实值                        |
| 恢复历史                   | 已保存任务后不传设置恢复                                                           | 返回 `gpt-6-astra / high`，以及原权限和 reviewer                   | 不用项目默认 `xhigh` 覆盖历史值；适配层覆盖普通与分页历史                                        |

空会话在首轮保存前调用真实 `thread/resume` 曾返回 `no rollout found`，因此恢复实验使用完成一轮任务后的历史。没有将模拟器结果当成真实模型执行结果，这段为 0.162.1 的历史记录，当时未验证所有模型/权限组合或冷启动覆盖优先级。0.163.0 的冷恢复、覆盖及观察到的权限边界见 [升级验证](codex-0.163.0-verification.md)。

2026-10-16 回归验证：在恢复响应前插入状态通知，原实现能稳定复现“会话当前配置”中审批和权限均为“未报告”。修复后的测试覆盖新建、恢复和 Fork 的响应与普通通知竞争，以及更新的配置通知（包括重复值和空值）优先于迟到响应。浏览器测试从没有实时通知的历史会话恢复，检查完整权限立即显示，并验证 `xhigh`、`max`、`ultra` 的不同图标、服务端确认和刷新恢复。

## UI 观察与取舍

2026-10-15 实际观察了 macOS Edge 中的 [ChatGPT Web](https://chatgpt.com/) 新聊天页面，页面未公开版本号。本机原生 ChatGPT 客户端禁止自动化读取，因此以下是 Web 参照，**没有声称核验原生 App 的同版行为**。只打开选择菜单，未发送消息或修改偏好；不发布含个人历史的参照截图。

观察到输入区旁有紧凑的模型/思考强度入口，展开后集中呈现模型和强度项；常用选择与输入任务处于同一视区。该观察支持“常用控件靠近输入区、按需展开更多设置”的建议，不证明 Codex 与 ChatGPT 的模型或强度枚举可以一一对应。

| 当前痛点                           | 优先级与本次处理                                                             | 后续边界                                                                         |
| ---------------------------------- | ---------------------------------------------------------------------------- | -------------------------------------------------------------------------------- |
| “继承”隐藏了具体模型/强度          | P0：直接显示服务器确认的具体值，删除继承选项                                 | 上游缺失字段明确显示未报告                                                       |
| 设置折叠后不易发现，展开表单占空间 | P1：项目/审批、模型/速度/推理/发送融合到发送栏；权限模式入口旁可展开只读详情 | 模型与推理强度使用 shadcn Select，共享模型设置弹层和 Fast 开关；权限模式保持独立 |
| 手动选择容易被误认作已经生效       | P0：待生效提示、当前值、撤销；服务器确认后清除                               | 运行中禁用，恢复保留值时继续提示                                                 |
| 同项目不同会话共享选择             | P0：会话草稿隔离；模型/强度显式保存为 Codex 默认值                           | 权限草稿继续按项目、会话隔离；不自动覆盖已有会话                                 |

实现入口：`src/codex/adapter.ts` / `mapping.ts`（RPC 映射）、`src/server/service.ts` / `projection.ts`（同步）、`src/web/hooks/useWorkspace.ts` / `useRuntimeDefaults.ts`（草稿与默认值）、`src/web/components/SettingsPanel.tsx`（展示）。

## Fast 速度模式

Max/Ultra 在模型设置弹层中保留仪表盘配色与点亮动效，强度值直接显示，不再重复展示额外的档位文字标签。

Fast 开关位于模型设置弹层内，显示闪电、模式名与开关状态；开启时输入栏的模型按钮也显示实心闪电。悬停或键盘聚焦显示当前状态、点击操作与用量说明，待确认时还显示服务器当前值。未报告状态通过提示及 `aria-pressed="mixed"` 表达，不冒充关闭。是否提供 Fast 由当前模型的 `model/list.serviceTiers` 决定（`priority` 归一为 `fast`），不支持的模型禁用开启操作；已有 Fast 状态仍可关闭，切换到不支持 Fast 的模型时提议恢复标准速度。其他上游档位原样显示，不误报成标准。模型与强度的默认值保存、Fast 的会话生效范围保持原规则。

仅提交用户改动：开启传 `serviceTier: "fast"`，关闭传 `serviceTier: null`，未修改则省略字段。该字段用于 `thread/start`、`thread/resume`、`thread/fork` 和 `turn/start`；不使用仅对单轮有效的 `serviceTierForTurn`。选择后先显示待生效提示，服务器响应或 `thread/settings/updated` 确认后才清除；执行期间禁止修改，草稿随现有设置按项目和会话隔离，可撤销。

2026-10-17 用本机真实 Codex 0.162.1 做无推理核验：`thread/start` 的 `fast` 请求返回 `priority`，显式 `null` 请求返回 `default`；通过子进程 `-c service_tier="fast"` 临时设为默认开启后，`null` 仍返回 `default`，没有改动全局配置。适配层将 `priority` / `fast` 统一为开启、`default` / `null` 统一为关闭，保留其他档位和缺失字段的区别。`config/read.service_tier` 用于新会话默认值；已保存的 `Thread` 元数据没有服务档位，恢复前显示未报告。恢复、新建和 Fork 的响应及实时配置通知提供已确认状态；网关实例重置清除旧的服务档位，元数据读取不会覆盖本实例已确认的值。

官方行为依据：[OpenAI Docs：Speed](https://learn.chatgpt.com/docs/agent-configuration/speed)。这次仅增加 UI 入口，不新增 `/fast` Slash Command。
