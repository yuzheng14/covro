## Reproduction

Use the already locked Node/pnpm dependencies and an already installed compatible Chromium. Do not download tools or browsers without dependency approval.

```sh
node --import tsx scripts/verify-preview-native.ts
node --import tsx scripts/verify-preview.ts
pnpm build
pnpm exec playwright test tests/e2e/dev-preview.spec.ts
```

For UI screenshots against an already running **explicit fixture** gateway, set `E2E_PORT` and run `node --import tsx scripts/verify-preview-ui.ts`. It uses the test-only loopback control listener, never a production bypass. `PREVIEW_SCREENSHOTS` captures the adapter probe's two project pages. `PREVIEW_ORIGIN` selects an already configured temporary test entry; `PREVIEW_SKIP_SSE` must describe the actual transport limitation and is reported as unexercised, not passing.

## Outstanding acceptance and support limits

- Real Tailscale and real authenticated Cloudflare Access end-to-end checks remain open. A suitable isolated authenticated entry is needed; existing live configuration must not be changed to manufacture a pass.
- Path adaptation does not virtualize Location. Routers hardcoded to `/` need an appropriate basename; computed imports, fixed localhost, worker/SDK request stacks and cookie/storage-based app login are not universally transparent. See the [English](dev-preview.md) and [Chinese](dev-preview.zh-CN.md) guides.
- A Content-Type allowlist is not proof of a side-effect-free GET; the registered development server can itself proxy other services. These are security boundaries documented by the Issue, not solved by process ancestry.
- The user confirmed no isolated authenticated entry is available and requested normal reviewable PRs, with these real-link checks deferred to the dev release after their review/merge. They remain uncompleted acceptance items, not passing results.

Cloudflare documents the [Quick Tunnel SSE limitation](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/).

## Source-only collector correction

The macOS collector now runs JS source with the built-in system JXA runtime. The C helper, binary, checksum manifest and compiler script were removed from the unmerged stack history. npm packaging requires `bin/process-darwin.js` and rejects other helper executable artifacts; the project still uses one npm package and the same Node 24 range.

Native process/socket/exit/port-reuse verification passed with JXA. Five kernel-byte fixture tests cover marker spoofing, duplicate/invalid markers, truncation, memory clearing and changed birth identity. These fixture tests are separate from the real OS tests. Real Chromium/Vite/OS two-project resources/routing/HMR/reconnect and WS/SSE revocation passed with zero unexpected browser errors; the UI Playwright flow passed in 15 seconds. Initial Windows proofs failed on PowerShell pointer conversions, directory-handle access and short-name path differences; these were fixed without relaxing ownership. Slow environment scanning was replaced with mutable UTF-16 arrays and system NUL scanning, retaining bounded reads and clearing raw buffers. UI fixture failures exposed POSIX-only launch/exit assumptions and a reload/selection race; the Windows simulator now runs through Node and persists history before forced termination. The complete rerun above passed, rather than counting those failed attempts as passes.

The local integrated suite passed **1,665 tests**, with **1 skipped**, using two workers. An earlier unrestricted run had two timing failures in adapter recovery and clone registration; their complete files passed serially (132 tests), and the bounded integrated rerun passed without changing those tests. TypeScript, full ESLint, formatting, production build, README compatibility/database declarations and npm package verification passed. Local macOS real-OS and two-project Chromium regressions also passed.

Windows support requires native x64 Node/processes, FullLanguage system PowerShell, readable process metadata and local directories with a live ancestor chain. ARM64/WOW64, UNC/mapped network directories and cross-Windows/WSL discovery are unsupported. Restricted process metadata fails closed; no permissions or sandbox policy are changed. PEB/process-parameter fields are guarded and may become incompatible with future Windows layouts.
