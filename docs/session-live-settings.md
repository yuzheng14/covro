## Exact protocol and source / 精确协议与源码

- [Protocol `common.rs`](https://github.com/openai/codex/blob/rust-v0.164.0/codex-rs/app-server-protocol/src/protocol/common.rs#L1076) marks `turn/settings/update` experimental. Its [request and status](https://github.com/openai/codex/blob/rust-v0.164.0/codex-rs/app-server-protocol/src/protocol/v2/turn.rs#L39) accept `threadId`, `turnId`, reviewer, model, effort, summary and service tier, returning `applied` or `targetUnavailable`. Covro deliberately sends neither model nor effort here.
- [App-server handler](https://github.com/openai/codex/blob/rust-v0.164.0/codex-rs/app-server/src/request_processors/turn_processor.rs#L215) submits `Op::TurnSettings` and waits for its result. Unknown settings are not a path to changing sandbox or approval policy. Covro's strict HTTP schema accepts only Fast and the permission selection, translating the latter to a reviewer only when both presets have the same known permission boundary.
- [Core publication](https://github.com/openai/codex/blob/rust-v0.164.0/codex-rs/core/src/session/step_activation.rs#L220) requires `step_model_switching` for model settings, including service tier. A reviewer-only patch does not need that feature. Publication checks task identity, cancellation, model/managed requirements and finally replaces `next_step_settings`; it does not mutate already captured steps or child sessions. Tasks that keep using frozen initial settings are unchanged.
- [Step settings](https://github.com/openai/codex/blob/rust-v0.164.0/codex-rs/core/src/session/step_settings.rs#L20) retain requested settings independently of future thread defaults, pin model metadata and resolve service tier against model and feature support. A catalog entry is not an entitlement or billing guarantee; backend/model policy can still reject a request. “Applied” means publication for subsequent captures, not that the in-flight request changed or that another step is guaranteed to occur.
- [TUI settings sync](https://github.com/openai/codex/blob/rust-v0.164.0/codex-rs/tui/src/app/thread_settings.rs#L162) translates `OverrideTurnContext` to `thread/settings/update`. [That handler](https://github.com/openai/codex/blob/rust-v0.164.0/codex-rs/app-server/src/request_processors/turn_processor.rs#L941) updates future thread settings. [Core thread settings](https://github.com/openai/codex/blob/rust-v0.164.0/codex-rs/core/src/session/thread_settings.rs#L35) do not publish active step settings. Unlocking the TUI-style picker alone therefore cannot establish live Fast or full permission changes.

完整权限模式不能用一个审核方字段模拟。仅在当前已确认是「请求批准」或「帮我批准」且新选择也为这两种模式时，两者相同的 `:workspace + on-request` 边界允许发布审核方。切换到完全访问、只读或自定义边界只保留下轮草稿。已有审批既不自动批准，也不改送自动审核。若要让沙箱/profile 或审批策略在本轮更新，需要上游新增公开接口和相应安全边界，本项目不通过中断重启或自动回答审批来替代。

## State and interaction / 状态与交互

Controls remain editable while a managed task runs. Model/effort hints say “Next turn”. Fast shows publication only after an `applied` receipt, with the exact version, thread feature and **current** model checked separately from the next selected model. Unsupported combinations stay pending for the next turn. Permission changes that affect sandbox/policy explicitly say “Next turn”. An upstream rejection, unavailable target or uncertain receipt never produces an applied claim.

执行中控件可编辑。当前轮次的 Fast/审核方回执与会话的下轮草稿分开管理；不把 `thread/settings/updated` 的未来默认值当作执行中确认。Fast 同时检查当前模型和拟用的下轮模型；切换模型会修正不受支持的强度/Fast 组合。`step_model_switching` 未启用时不尝试发布 Fast，也不自动修改用户的功能开关。

Each browser tab keeps next-turn drafts per session through selection changes and refresh. New-session project drafts retain their existing page lifetime. Model/effort default saving remains the existing explicit picker behavior described in [runtime settings](runtime-settings.md); permission/Fast publication never writes global defaults. Other browsers have their own drafts. Updates are serialized per thread in the browser and gateway; the final explicit valid edit wins. Undo also queues a rollback when a live write is still pending. Lost/uncertain operations are reconciled by identity, never automatically replayed.

下轮草稿按会话隔离，在同一标签页刷新、切换会话和短暂断线后保留；其他标签页不共享草稿。模型/强度保存为新会话默认值的既有行为不变。连续修改和撤销按会话排队，回执只用于对应 turn/epoch。本轮结束、失败、停止或实例重置后清除本轮确认，未来草稿保留到下次显式发送。执行中追加要求只发送 `turn/steer`，不附带下轮模型/强度；容量自动重试仍使用原执行快照。

This feature adds no Slash Command entry. `/skills` and `/usage` remain outside the existing command-entry scope; #69 remains the long-term tracker, not an issue closed by this feature.

## Verification / 验证

`node --import tsx scripts/verify-live-settings.ts --config <isolated config selecting an existing 0.164.0 binary>` uses a fresh temporary `CODEX_HOME`, local HTTP Responses stub and native Code Mode. It never loads account credentials, calls real inference or changes the real service. The model replies are deterministic fixtures; this is real-binary protocol/execution verification, not real-model behavior or entitlement verification.

真实二进制 + 本地 stub 验证：首个模型请求在途时发布 Fast；真实人工命令审批等待期间发布审核方，确认旧请求仍待处理，再显式拒绝；同轮后续模型请求为 `priority` 且模型/强度不变；下一轮使用新模型/强度并清除 Fast；已结束目标返回冲突。结果见 [machine-readable record](session-live-settings-results.json)。没有自动批准测试审批。

Fixture integration/browser tests additionally cover feature-disabled Fast, unsupported/rejected/stale targets, strict field validation, ordered edits and undo, per-session isolation, receipt races, refresh, retained human approval, all four UI languages, desktop and 320/390px layouts. Screenshots show the running production frontend with the explicit simulated-mode banner. No authenticated real-model run or mobile hardware run was performed for this feature.
