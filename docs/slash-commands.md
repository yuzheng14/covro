# 输入框 Slash 命令

在任务输入框开头输入 `/` 打开菜单。继续输入命令名或中文说明可筛选，例如 `/st` 或 `/历史`。完整名称优先，其次是名称前缀，再匹配说明。使用 ↑ / ↓ 选择、Enter 执行、Esc 关闭菜单，也可点击菜单项。Shift + Enter 仍然换行，中文输入法确认候选词不会执行命令。

只有去除开头空白后以单个 `/` 开头的内容进入命令模式。正文中的 `/` 和 URL 仍是普通消息。要发送以 `/` 开头的文本，请输入 `//`：例如 `//help` 会发送普通消息 `/help`。未知命令、不支持的参数或附带图片的命令都会明确提示并保留草稿，不会作为消息发给模型。

完整命令清单与支持状态统一维护在 [Issue #69](https://github.com/yuzheng14/codex-web-ui/issues/69)。适配 Codex 新版本或修改命令功能时，同步更新该 issue。

复制回答使用每轮底部完成信息旁的「复制回答」按钮，无需 `/copy` 命令。按钮复制本轮最后一条非空 AI 回复的 Markdown 原文，保留代码围栏、缩进和换行，不拼接用户消息、此前的过程回复、工具输出或完成信息。仅已完成且有回复的轮次显示按钮，历史回复同样可复制。浏览器拒绝或不支持剪贴板访问（例如部分 HTTP 环境）时会提示手动选择回答复制，可再次点击重试；成功后短暂显示「已复制」。`/copy` 不加入命令菜单。

## 已实现的范围

首批命令使用项目已有的网页流程和网关接口，不向终端输入文字，也不透传任意 Codex CLI 命令。当前实现依据已验证 Codex **0.164.0** 与仓库中已经验证的 app-server 接口。CLI 自身的完整命令范围独立维护，可查阅 [Codex CLI 命令参考](https://learn.chatgpt.com/docs/developer-commands?surface=cli)。

`/rename <名称>` 必须提供名称，`/plan [任务]` 可选提供任务，`/review [自定义要求]` 可提供审查要求；其他命令无需参数。

`/review` 通过原生 `review/start` 在当前会话中审查项目的未提交改动，包含已暂存、未暂存和未跟踪文件；不会把命令拼成普通提示词。须先选择并恢复会话，等待当前任务结束；归档、离线、兼容性未确认或提交待核对时不能开始。审查复用现有审批、真实轮次状态、中断与回执核对流程，完成结果会显示在当前对话中。提交被接受不表示审查已经完成。

本轮审查使用会话当前已生效的模型与权限配置，输入框中尚未应用的设置不随 `/review` 提交。无参 `/review` 打开目标选择器，可选未提交改动、基础分支、指定 commit 或自定义要求；分支名称和 SHA 由用户填写。`/review 检查并发边界` 直接使用原生自定义目标，不将文字当成分支或自造标志参数。非 Git 项目或上游拒绝会显示实际错误并保留命令输入，不自动重试未知结果。

`/new`、项目入口与“新建会话”共用起始输入页。打开输入页不创建 Codex thread，不添加临时历史条目；已有项目草稿继续保留。用户真正发送首条消息时，才使用所选项目及设置创建会话，然后发送消息；创建失败保留草稿，创建成功但发送失败时重试复用同一会话。首条消息派发后保持历史入口，便于核对未知结果。点击 `/new` 不会中断原会话的任务或删除历史。

手机和平板的 Enter 仅换行，Slash 菜单也不会通过 Enter 执行；点击命令项或“执行命令”按钮提交。桌面仍使用原有键盘快捷键。设备判定和外接键盘边界见[输入说明](usage.zh-CN.md)。

## 重命名边界

`/rename 发布前检查` 使用原生 `thread/name/set`，不新增对话消息，也不修改会话 ID、历史、项目或 Fork 关系。名称允许空格，不需要引号；引号会成为名称的一部分。提交后顶部和侧栏立即显示待确认的新名称；成功回执携带上游摘要与事件游标，再与实时更新合并。明确失败恢复最新服务端名称并保留重试草稿；超时或断线保留待确认状态，用原操作 ID 核对，刷新后仍能继续核对。此入口独立于侧栏内联编辑（#28）；首版不提供 CLI 无参数时的名称输入界面，输入 `/rename` 会显示必填参数用法。

重命名会停止此运行实例为该会话进行的自动命名。已经发出的自动名称写入必须先确认，再写入手工名称；自动写入超时结果不明时，手工重命名也保留不确定结果，不能自动重试，需核对并重启运行实例后再操作。重命名只接受当前网关已恢复的会话，无法改名其他进程占用的历史。任务可以继续执行，但同一会话的重命名与归档操作必须等前次回执确认。

## 回执、草稿和故障处理

执行操作复用网页现有的操作 ID、`workspace.run`、回执追踪和错误提示。只有 `acknowledged` 才显示操作已被接受；Fork 还必须收到目标会话 ID，才显示成功并将反馈归属到新会话。中断成功只表示“已提交中断请求”，任务是否结束以之后的真实状态为准。

压缩请求未收到新任务事件或运行时重启时，执行占用会保守保留；请通过 `/status` 核对，确认旧任务已结束后再解除占用。

失败、缺少回执、`accepted`、`dispatching` 或 `unknown` 都保留命令输入。网络异常沿用现有操作 ID 查询，不自动重发；先查看页面错误或使用 `/status` 核对。命令执行时会重新核验当前状态，项目或会话已经切换时拒绝使用旧命令上下文；提交期间重复 Enter 或点击不会重复执行同一草稿。

普通消息和图片仍按原流程发送、追加要求；会话操作命令不新增用户消息；带任务的 `/plan` 保存任务正文，`/init` 保存服务器提供的项目说明生成任务。成功只清除本次已执行且未被继续编辑的命令输入，其他会话和项目草稿继续独立保存。

## Markdown 导出范围

`/export` 使用经过身份认证和项目归属检查的 `GET /api/threads/:threadId/export` 逐页读取 Codex 本次返回的已保存历史，包括原生分页中的全部轮次和条目。它不使用实时消息或浏览器里可能截断的历史缓存，不创建任务、恢复会话或改变执行状态。浏览器通过普通下载保存 `.md` 文件，不访问剪贴板，也不要求 HTTPS。

文件包含用户消息、助手消息、计划、代码审查结果、命令及其已保存输出、文件差异。进入审查和上下文压缩会保留简短事件说明，不附带内部上下文。工具输出使用独立代码块，保留换行和内容中的 Markdown 围栏。图片只记录数量，不嵌入图片内容、地址或本地路径；推理、未支持类型的内部内容、审批载荷和运行配置不导出，并在相应位置标明省略。普通消息、命令输出或文件差异中用户本来可见的内容会原样保存，导出不会自动识别或删去其中的敏感文字。

这是**本次读取到的已保存历史**，读取并非原子快照，不承诺恢复 Codex 已删除或未持久化的内容。正在执行、状态未知、执行记录待核对、读取期间状态变化或条目已截断时，文件名增加 `-partial`，正文和网页反馈明确说明它不是完整的最终结果。已知缺少历史轮次、读取失败、运行进程变化或项目归属失效时，不下载缓存替代品，命令草稿保留以便重试。下载提示只表示浏览器已开始下载，不代表用户已确认保存文件。

### 上下文压缩状态

`/compact` 与自动压缩使用相同的状态展示：收到压缩条目的开始通知后，会话顶部显示「正在压缩上下文…」；完成后在历史中显示「上下文已压缩」。压缩完成不会提前结束整轮任务。失败或中断会结束进行中提示，有明确错误时显示原因。浏览器断线期间标注「上次已知」，服务端状态无法确认时显示未知，不推测进度。

## Plan 模式

`/plan` 只为当前工作区或会话选择下一轮 Plan 模式，不创建空会话；`/plan 对比两种方案` 会使用所选设置提交任务。模型设置中的协作模式选择器也可选择 Plan 或执行模式。设置显示待生效，只有 Codex 的真实设置通知或恢复响应确认后才作为当前模式；未报告的模式不推测为执行。

模式通过 Codex 0.164.0 的实验 `turn/start.collaborationMode` 传递，`developer_instructions: null` 使用上游内置指令。恢复响应与 `thread/settings/updated` 用于确认；实验扩展集中在 `src/codex/collaboration.ts`，不修改生成类型。模型和推理强度沿用当前选择；不写全局配置，不把模式名称拼成普通提示词。

Plan 验证：真实 Codex 0.164.0 + 隔离 CODEX_HOME + 本地 HTTP 模型 stub 已验证 Plan/执行模式切换、上游内置 Plan 指令及恢复回读；没有真实模型推理。浏览器回归覆盖首条消息、无参草稿、模式切换及桌面/窄屏页面。

审查目标扩展已通过真实 Codex 0.164.0 与隔离本地 HTTP 模型 stub 验证四类 `review/start` 目标及真实轮次结束；这不是真实模型审查质量验证。浏览器覆盖目标选择、行内自定义要求、取消、错误、重复提交与中断，分支和 commit 当前使用手工输入。

## 项目初始化

`/init` 使用显式任务类型，由服务端选择固定的项目说明生成指令，经正常 `turn/start`、审批、执行状态、中断与回执流程提交。它可作为工作区第一条任务；普通消息或 `//init` 不触发该任务类型。当前模型、模式和权限仍生效，提交成功不表示文件已创建，应查看任务实际结果。

服务端按已验证的工作目录检查 `AGENTS.md`，文件、目录或符号链接已存在时均拒绝派发，读取失败也不继续。任务指令同时要求再次检查并保留已有内容。首次生成与外部编辑不是原子事务；若文件在任务期间出现，代理必须遵守不覆盖的指令。

## 工作区差异

`/diff` 根据服务端验证过的项目或会话目录读取 Git 工作区，支持暂存、未暂存和未跟踪三个分组。快照标记读取时间，可手动刷新；读取失败显示实际错误。子目录项目只读取该目录范围，并排除其他受管会话的独立工作目录。禁用外部 diff、textconv、fsmonitor 及读取时配置的 clean/process/smudge 过滤器，不执行 Git 钩子。使用自定义过滤器的仓库（例如 LFS）展示未经该转换的索引/工作树差异。

每组 Git 输出最多 512 KiB，未跟踪文件最多 80 个、单文件最多 128 KiB、合计最多 512 KiB；超限明确标记部分内容。二进制文件显示元数据，符号链接只显示链接文本，不跟随目标。查看期间文件可能继续变化，不承诺原子快照。

## 拒绝操作的重试授权

`/approve` 读取当前受管、非归档、空闲会话在本次运行中最近 10 条自动审核拒绝记录。选择后展示原操作、目录与拒绝原因，必须点击“单次授权”；打开、取消和无记录都不授权。使用原生 `thread/approveGuardianDeniedAction`，它仅注入授权上下文，不启动新任务；用户可随后明确要求继续。默认权限与自动审核方不变。

浏览器仅提交记录 ID 与显式确认，服务端保留并按 0.164.0 协议转换被审核的原操作，拒绝任意客户端事件。每条身份在派发前消耗，超时不重放；已有操作 ID 的回执沿用持久核对流程。运行时重启后旧记录失效，不从旧 UI 展示重建授权。工作区归属与兼容性在派发前重新检查。

验证：真实 Codex 0.164.0 + 本地模型 stub 接受转换后的测试拒绝载荷，并确认授权不新建轮次；这不是一次真实 Guardian 风险判断或外部命令执行。浏览器覆盖选择、取消、重开、显式确认和单次消耗。

## 会话摘要

`/recap` 在当前受管、非归档且空闲会话中，从最新一页历史选取近期用户及助手消息，最多 24,000 字符、每条最多 6,000 字符；不读取推理、审批载荷、图片或工具输出。历史分页、条目或字数有省略时明确标注部分内容。摘要语言使用提交时的界面语言。

它需要一次额外模型请求，通过隔离的只读临时 thread 生成结构化摘要，禁用工具、MCP、Apps、Plugins、hooks、技能、记忆与 goals，超时/失败中断并退订临时 thread。原会话历史、标题、上下文与执行占用不变；它不代替 `/compact`，也不保证还原全部历史。结果在独立窗口显示，关闭窗口不会发送新任务。未知回执按原操作 ID 核对，不自动重发模型请求。

验证包含真实 Codex 0.164.0 + 本地模型 stub 的隔离请求与源历史不变、临时工具交互拒绝与超时清理，以及真实浏览器的桌面/手机结果窗口。未使用真实模型推理评估摘要质量。
