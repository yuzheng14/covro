# 架构与 review 边界

浏览器以 HTTP 提交操作，以 WebSocket 接收有界事件流；网关持续持有一个 Codex 子进程。浏览器断线只删除连接订阅。没有任意上游 RPC 透传接口。

| 层       | 位置                                          | 责任                                                 |
| -------- | --------------------------------------------- | ---------------------------------------------------- |
| 应用合同 | `src/shared`                                  | 浏览器可用 DTO、请求校验、统一错误                   |
| 上游适配 | `src/codex`                                   | CLI 生成协议、UTF-8 JSONL、RPC、握手、活动与审批映射 |
| 持久化   | `src/server/db`、`drizzle`                    | Drizzle 同步事务、唯一操作 ID、执行占用、迁移        |
| 领域服务 | `projects`、`service`、`projection`、`events` | 路径归属、任务协调、状态投影、人工请求、恢复         |
| 网络入口 | `config`、`auth`、`http`、`websocket`、`main` | 校验、Access、静态产物、连接上限、生命周期           |
| 浏览器   | `src/web`                                     | HTTP、按会话恢复、持久操作引用、视图与交互           |

派发 turn 前，操作记录与执行标记在同一短 SQLite 事务中提交；提交后才写上游。数据库事务中没有 await。操作 ID 冲突走唯一约束，内容摘要不同拒绝；相同内容返回原记录。超时或退出后不重发原 prompt。

执行标记保留启动操作 ID、threadId、turnId、workspaceKey、codexEpoch。真实终态释放对应标记；人工核对只解除原标记，不能解除后来任务。RPC 回执和任务终态分别处理。

读取带已知 turnId 执行标记的缓存详情（包括发送下一轮前的读取）时，网关会核实上游历史，同一执行的并发核实合并为一次读取。仅当原任务存在明确终态、历史没有活动任务、读取期间运行实例与实时投影未变化且标记仍属于原操作时释放；无法读取、缺少 turnId 或仅有 idle 状态均不释放。同步 SQLite 事务与 `execution_markers_active_thread` 唯一索引只防止同一 thread 重复启动活动 turn，不阻塞 steer，也不限制其他 thread。

投影按上游 thread/turn/item ID 合并。浏览器以 incremental 订阅接收 threadPatch：元数据整体更新，轮次和消息按稳定 ID 更新，文本以绝对偏移追加；流式事件只检查对应条目，不克隆或序列化旧历史正文。首次连接、过期游标或过大的替换事件返回 resync，浏览器通过 GET /api/threads/:threadId/snapshot 获取完整历史页及同一同步边界的游标，再订阅该游标之后的事件。HTTP 读取期间的变化由有界重放缓存补齐；缓存过期重新读取，旧响应不能覆盖较新的投影或其他会话。发送缓冲限制保留，完整历史不因 WebSocket 预算被裁成预览。未指定 incremental 的旧订阅仍提供有界初始快照。全局运行状态与会话游标分开跟踪，刷新不复用单独残留游标。

人工请求保留原始 RPC ID 与运行代次，额外权限和 MCP 交互与命令审批共用待处理、回答中、已回答、失效的生命周期。额外权限的授权范围由适配层根据原始请求构造，浏览器仅提交合法决定；MCP 表单先转换为浏览器可用的字段合同，并在派发前校验回答。权限目标和表单约束属于控制信息，快照压缩不能移除。未支持的交互会显示兼容性错误，未支持的 MCP 表单仍提供拒绝和取消操作。

自动审核通知转换为独立的信息项，按 thread、turn 和 review ID 合并，与被审核工具的 item ID 分开。同一工具的多次审核可分别保留，重复或迟到的开始通知不会覆盖终态。自动审核记录不进入人工请求列表，不占用审批操作，也不改变任务执行状态；操作目标和原因参与既有内容大小限制。其来源为当前网关收到的实时通知，不是持久化历史。

`GET /api/projects/:projectId/threads` 返回分页会话摘要与读取开始时的事件游标。摘要只包括身份、项目、标题、来源、状态、更新时间、待处理数量及最后一轮状态，不包含正文、工具内容或审批参数；原有会话列表与详情 API 保持不变。`/ws?overview=1` 显式订阅跨项目摘要变化，普通 `/ws` 维持原有消息合同。摘要使用独立监听通道，不占详情重放缓存，重连后由 HTTP 列表恢复；详情仍只订阅当前会话。`unsubscribe` 清理详情订阅，保留运行状态和已启用的摘要订阅。

浏览器按项目维护摘要列表、分页与错误；详情缓存单独持有会话投影与恢复游标。HTTP 读取序号和摘要事件游标共同防止迟到响应回滚状态。切换会话只替换同一 WebSocket 的详情订阅，真实重连才重新读取各项目列表。项目选择、会话草稿、执行设置与创建/Fork 的导航意图分别记录，用户切换位置后迟到回执仅更新原项目。

自动命名对齐 [Codex CLI 0.162.1 的终端实现](https://github.com/openai/codex/blob/rust-v0.162.1/codex-rs/tui/src/app/thread_title.rs)。适配层 `ThreadTitles` 在 `item/completed` 用户消息事件到达时，为尚未命名的受管会话启动异步命名；创建、恢复及 Fork 均登记候选，同一会话只允许一个在途命名任务。`thread-title-policy.ts` 复用 CLI 的模型选择、提示词、JSON Schema 和结果清理规则：OpenAI provider + ChatGPT 账户 + 可用模型目录包含 `gpt-5.6-luna` 时选该模型及 low effort，否则选当前会话模型且不覆盖 effort；整个提示词限制 960 UTF-8 字节，结果限制 36 个 Unicode 字符，拒绝多余 JSON 字段。

命名使用同一 app-server 上的独立 `ephemeral` 会话，来源为 `thread_title`，不进入用户历史。沿用 CLI 的临时请求隔离：清空工作区根、环境和动态工具，关闭 shell、MCP、Apps、插件、skills、hooks 等能力，并额外显式关闭浏览器和 computer use。自定义权限 profile 原样保留并核验响应；其余情况要求只读权限，审批策略由服务端继承，临时交互请求由适配层拒绝。实验性字段在本模块按已核对的协议补充类型，不改写生成文件。配置查询只提取 MCP 名称并覆盖 `enabled`，不回传可能已脱敏的配置值。

生成结果在保存前重新检查 `thread.name`，名称更新通知会取消在途命名。标题通过 `thread/name/set` 持久化，沿用 `thread/name/updated` 的详情与概览推送。启动、推理阶段分别有 30 秒期限；失败或断线保留预览，仅中断临时 turn 并取消订阅，不改变用户任务状态。创建通知可早于或晚于响应，完成通知可不带 items，均通过独立生命周期与 `item/completed` 处理。失败后保留未命名候选，直到下一条用户消息才重试；恢复或 Fork 本身不触发命名，也不批量改写历史。重启后通过正常 resume 重新登记候选。

不同 thread 可在同一目录并行，包括等待审批、等待输入或旧执行未知的情况。`workspaceKey` 保留为项目与执行的诊断信息，不再作为互斥键。迁移 `0002_allow_parallel_threads.sql` 删除旧数据库的工作区唯一索引并保留现有执行记录；需要文件隔离时由用户自行使用 Git worktree。

`POST /api/threads/:threadId/fork` 接受 `{ clientOperationId, settings? }`，返回标准操作回执，成功结果为 `{ threadId, forkedFromId }`。服务端只读源会话并校验注册项目归属，再将其 canonical cwd 交给适配层调用 `thread/fork`；客户端不能指定目录。新 ID 注册为当前进程持有的会话，历史由 Codex 保存，无需新增数据库表。

Fork 可以用于外部、运行中或结果未知的会话，不要求先释放原会话占用；Fork 本身不会 resume、interrupt 或解除原执行标记。新会话使用原目录，可以立即与原会话并行执行。省略 `lastTurnId` 复制当前已保存历史；不提供指定历史位置或创建 worktree 的功能。相同操作 ID 去重；上游 Fork 成功但历史加载失败时保留 `unknown`，错误详情包含已知的新 ID，不自动重发。

评审顺序按照提交链由基础合同、真实生成协议、传输适配、持久化、协调服务、网络安全到浏览器与交付。生成文件单独成层，GitHub 将其标记为 generated；人工代码按职责分层评审。使用 GitHub 原生 Stacked PR 关联依赖，按栈底向上合并。

## 项目注册与生命周期

项目注册保存在 SQLite 的 `project_registrations` 表，记录稳定 ID、原始路径、固定的 canonical root、显示名称和移除时间。启动时导入 JSON 中尚未注册的 ID；数据库保留页面重命名和移除状态，已存在 ID 不能重新绑定其他路径。空项目列表允许启动。旧配置中同目录的多个 ID 保留兼容性，新增页面项目按 realpath 去重；重新添加已移除目录恢复原 ID，旧别名中即使仍有同目录项目启用，也优先恢复已有的移除身份，不新建重复身份。同目录旧别名的未关联历史优先归属最早注册且仍启用的 ID。

`POST /api/projects` 接受 `{ path, name? }`，`POST /api/projects/:id/rename` 接受 `{ name }`，`POST /api/projects/:id/remove` 接受空对象。管理接口沿用统一的认证、Host、Origin、请求大小和严格字段校验，不依赖 Codex 是否就绪。目录必须是可读取、可进入的真实目录；任务接口仍不接受任意 cwd。路径重新指向其他真实目录时，注册项标记为不可用。

移除使用 tombstone，不修改项目文件或 Codex 历史。已有 `thread_links` 决定历史归属，父子目录列表不能改写关联；尚未关联的历史按最深的注册根目录分组。活动和待核对执行标记、进行中或未核对的创建/恢复/Fork 操作阻止移除；元数据操作将项目 ID 持久关联到操作记录，重启不能绕过保护。未结束的请求不能通过人工核对提前解除保护。

`/ws?overview=1` 通过独立的 `projects` 事件推送注册列表，普通 `/ws` 保持兼容。浏览器在初次加载、重连和手动刷新时读取注册快照，使用请求序号与注册变更版本拒绝迟到响应；移除项目同时使该项目的会话列表请求和详情缓存失效，当前选择退回剩余项目或空状态。

页面仅对当前选中的未受管会话自动提交一次恢复操作，由 Codex 在 `thread/resume` 时获取跨进程写入权。并行浏览器请求共享同一次获取；服务端读取历史和订阅仍不触发恢复。明确失败作为当前实例的临时 `resumeError` 发布，成功、重试或实例重置会清除。占用提示只来自 `THREAD_IN_USE`，与未受管标记及执行状态独立。回执未知仍走原操作核对流程，页面刷新不会重新提交。

## 会话归档

归档状态由 Codex 原生管理。网关调用 `thread/archive` / `thread/unarchive`，两个列表 API 将 `archived` 和分页游标传给 `thread/list`；不另设 SQLite 归档字段。CLI 中归档的历史也可发现，服务重启后读取同一份状态。`thread/read` 没有归档字段，因此详情通过原生归档索引核实状态，不依赖不稳定的 rollout 路径；列表、查询和归档通知以请求序号防止迟到结果覆盖新状态。

`POST /api/threads/:threadId/archive` 接受严格的 `{ clientOperationId, archived }`，沿用操作回执、项目归属、兼容性校验和未知结果核对流程。操作在途及未核对期间阻止该会话继续执行和项目移除。状态已符合目标时不重复派发；响应丢失只读取原操作，不自动重发 RPC。上游失败会重新读取归档状态并清除可能失效的受管写入权，不写入虚构的本地成功状态。

原生归档会卸载会话，并归档其派生子任务。网关在归档前检查原生状态、缓存历史、活动执行标记、待办和并发恢复；adapter 另查已加载会话的父子关系，阻止归档有活动子任务的父会话。运行中、等待审批/输入和结果待核对时拒绝归档，不通过归档隐式中断任务。归档与发送/恢复互斥；取消归档恢复原 ID，再由正常恢复流程重新取得写入权。原生归档可能部分完成，最终状态以 Codex 查询与通知为准。

侧栏会话行提供归档/取消归档图标，悬停或键盘聚焦时 tooltip 显示操作或不可操作原因，Escape 关闭提示。“已归档会话”入口可查看保留的历史。当前会话状态变化时切换对应列表并保持选中；已归档会话不自动恢复，输入区保留草稿但不能提交。实时摘要及列表版本检查避免旧响应重新插入已移出的条目。
